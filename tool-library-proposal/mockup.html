Tool library redesign: interactive mock-up

One dialog, opened from the Tools cell of the ribbon. The list folds into a rail when you open an item (variant B). Holders are first-class items with their own list and editor, and each field has one home. The mock-up is interactive.

One home for each field. A tool owns its cutter and shank. A holder owns its taper, clamp and shape. The assembly of the two owns one number: the stick-out. The gauge length is computed and shown, not typed.

What changes against today

Today: "Tool library" is a tab beside Properties. It lists the built-in catalog with an Add button. A tool is edited on a property page with four folded groups (Geometry, Holder, Cutting data, Catalog), the holder is a combo box inside the tool, and the drawing is a 260 px square.
Proposal: one dialog with two kinds of item, Tools and Holders. Each has a list, a rail and an editor with a large dimensioned drawing. A tool picks a holder and sets the stick-out; the holder's own data is edited in one place and all tools that use it follow. Recipes are a tab of the tool. Each Apply stays one undoable command (AddTool, ChangeTool, SetToolBody, ApplyCuttingData), so the MCP tools do not change.

Open questions for the maintainers

1. Dialog or dockable window: may the user keep it open beside the viewport?
2. "My library" needs a user library store. Issue #3645 plans one; this dialog would be its front end.
3. Holders are built in today (holder_library.rs). User-made holders need a store and a file format. (#808, #3648)
4. Recipes: one row per material on the tool (as CuttingRow today), or a named, shared object? (#3393)
5. Tool + holder + stick-out is the smallest "assembly". Does this dialog become the assembly editor of #2452 / #3644 to #3648 (extensions, inserts)?
6. Flutes in the drawing: decoration only, from flutes and helix_deg. No new geometry law.
